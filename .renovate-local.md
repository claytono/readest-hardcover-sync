# Renovate merge guidance

Read by the local Renovate merge skill. The public renovate-eval action and
skill do not read this file.

## What changes what runs

The service image is built from `Dockerfile`, `.dockerignore`, `go.mod`,
`go.sum`, `cmd/`, `internal/` and `static/`. An update to any of them changes
what runs: deploy and check it after merging, as below. Every other update,
such as GitHub Actions, pre-commit hooks or the Nix development shell, only
needs CI.

## Deploying, after merging

A merge to `main` builds `ghcr.io/claytono/readest-hardcover-sync:edge`
(`.github/workflows/edge.yml`). claytono/infra runs that image in the
`readest-hardcover-sync` namespace (`kubernetes/readest-hardcover-sync/`), but
the pod only pulls a new image when it restarts. Once the edge run for the
merge commit has passed, restart it:

```bash
kubectl -n readest-hardcover-sync rollout restart deployment/readest-hardcover-sync
```

## Checking it works

- The rollout finishes, and the new pod's image was built from the merge
  commit: the `org.opencontainers.image.revision` label of the pod's image
  digest, read with `skopeo inspect`, equals the merge commit.
- The service syncs as soon as it starts. Its log shows `sync tick complete`
  after the restart, with no `initial sync tick failed` or other errors.
- Both credential checks succeed:

  ```bash
  kubectl -n readest-hardcover-sync exec deploy/readest-hardcover-sync -- readest-hardcover-sync check-readest-auth
  kubectl -n readest-hardcover-sync exec deploy/readest-hardcover-sync -- readest-hardcover-sync check-hardcover-auth
  ```
